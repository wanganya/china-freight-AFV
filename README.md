# china-freight-AFV
# Overview
This repository contains all codes of the paper - **Spatially Differentiated Electrification Strategies for China’s Intercity Freight Transport: Multi-scale Actionable Insights from Nationwide Micro-simulations**

Note that the full dataset can be requested through Email.

# Installation
It is highly recommended to download AnaConda to create/manage Python environments. You can create a new Python environment and install required aforementioned packages via both the GUI or Command Line. Typically, the installation should be prompt (around 10-20 min from a "_clean_" machine to "_ready-to-use_" machine, but highly dependent on the Internet speed).

- via **Anaconda GUI**
  1. Open the Anaconda
  2. Find and click "_Environments_" at the left sidebar
  3. Click "_Create_" to create a new Python environment
  4. Select the created Python environment in the list, and then search and install all packages one by one.
     
- via **Command Line** (using **_Terminal_** for macOS machine and **_Anaconda Prompt_** for Windows machine, respectively)
  1. Create your new Python environment )
     ```
     conda create --name <input_your_environment_name> python=3.10.6
     ```
  2. Activate the new environment 
     ```
     conda activate <input_your_environment_name>
     ```
  3. Install all packages one by one 
     ```
     conda install <package_name>=<specific_version>
     ```

# Usage

## Download the repository

Clone or download the repository to your local disk.

```bash
git clone https://github.com/wanganya/china-freight-AFV.git
cd china-freight-AFV
```

All executable scripts are stored under:

```text
./codes/
```

The complete workflow should be executed in the following order:

```text
Stage 1: 01FreightTripODGeneration.py
        ↓
Stage 2: 02DetailedFreightTripsGeneration.py
        ↓
Stage 3: SimulationOptimization/0preprocess/PreDistanceCorrection.py
        ↓
Stage 4: SimulationOptimization/main.py
```

Stage 1 feeds Stage 2. Stage 2 and Stage 3 provide key inputs to Stage 4.

The repository-level data structure is documented under `./data/`.

---

## Stage 1. Generate intercity freight OD demand

### Data preparation

Prepare the two Stage 1 input files under:

```text
./data/input/freight_demand/
├── EFVTrip2019CoorReviseCityDiffODCargo.txt
└── 2019CityFreVoluaddCodeRevisedDiffODFinalFinal.txt
```

The first file contains the OD-based 2019 freight vehicle survey records. The second contains city-level highway freight volume statistics used to constrain and expand the survey OD records.

The current script contains local Windows paths. Before running, update the path settings in:

```text
./codes/01FreightTripODGeneration.py
```

### Run

```bash
python ./codes/01FreightTripODGeneration.py
```

### Output

The principal Stage 1 output is:

```text
EFVTrip2019CoorReviseCityDiffODExpandImproved.txt
```

For a repository-style workflow, store it under:

```text
./data/interim/freight_od/
```

The current Stage 2 code reads this exact filename, so the Stage 1 -> Stage 2 filename interface is aligned.

---

## Stage 2. Generate detailed seasonal freight trips

### Data preparation

Stage 2 uses:

1. the expanded OD demand generated by Stage 1;
2. the highway network used for route generation/assignment;
3. monthly highway-flow distribution data;
4. hourly highway traffic-volume observations.

Recommended structure:

```text
./data/interim/freight_od/
└── EFVTrip2019CoorReviseCityDiffODExpandImproved.txt

./data/input/road_network/
└── OSM_Highway_no2nd_Code.gpkg

./data/input/traffic_volume/
├── monthly/
│   └── MonthDistribution.txt
└── hourly/
    ├── 20190114_update.xls
    ├── ...
    └── 20191112_update.xls
```

The current script contains local Windows paths. Update the Stage 2 path settings in:

```text
./codes/02DetailedFreightTripsGeneration.py
```

### Run

```bash
python ./codes/02DetailedFreightTripsGeneration.py
```

### Outputs

Stage 2 generates preprocessing, constraint, path, and assignment files. The principal files used by the subsequent simulation are:

```text
optimized_assignment_Winter.txt
optimized_assignment_Spring.txt
optimized_assignment_Summer.txt
optimized_assignment_Autumn.txt
```

A recommended location is:

```text
./data/interim/trajectory_generation/
```

The current Stage 4 trajectory filename mapping has been updated to read these four `optimized_assignment_<Season>.txt` files.

Stage 2 also generates files such as:

```text
preprocessed_od.txt
unique_ods.txt
corrected_coefficient_<Season>.txt
constraints_4hour_<Season>.txt
constraints_summary_<Season>.txt
paths_<Season>.txt
TrafficVolume_<Season>.png
```

### Trajectory schema requirement

For direct Stage 4 execution, the trajectory input must satisfy the fields expected by the Stage 4 loader/simulator, including a valid vehicle ID, date, departure time, path, and cargo weight. See `MAINTAINER_NOTES.md` in the supplied documentation bundle for the current schema-interface check.

---

## Stage 3. Generate city-level distance correction factors

### Data preparation

Stage 3 uses:

```text
./data/input/city_boundary/
└── City.shp
    # plus .shx/.dbf/.prj and optional .cpg

./data/input/road_network/
└── ChinaHighway.gpkg
    # or a configured equivalent

./data/input/traffic_volume/hourly/
└── YYYYMMDD_update.xls
```

The current script contains local Windows paths. Update them in:

```text
./codes/SimulationOptimization/0preprocess/PreDistanceCorrection.py
```

### Run

```bash
python ./codes/SimulationOptimization/0preprocess/PreDistanceCorrection.py
```

### Outputs

The principal output is:

```text
CityDistanceCorrection.pkl
```

and the script also generates:

```text
CityDistanceCorrection_sample.json
```

For a repository-style workflow, store them under:

```text
./data/interim/distance_correction/
```

`CityDistanceCorrection.pkl` is subsequently loaded by Stage 4.

---

## Stage 4. Run the AFV micro-simulation and multi-objective optimization

### Data preparation

Stage 4 uses the Stage 2 and Stage 3 intermediate results together with the simulation/optimization inputs.

Recommended structure:

```text
./data/interim/trajectory_generation/
├── optimized_assignment_Winter.txt
├── optimized_assignment_Spring.txt
├── optimized_assignment_Summer.txt
└── optimized_assignment_Autumn.txt

./data/interim/distance_correction/
└── CityDistanceCorrection.pkl

./data/input/road_network/
└── ChinaHighway.gpkg
    # sample: ChinaHighway_demo.gpkg

./data/input/traffic_volume/hourly/
└── YYYYMMDD_update.xls

./data/input/station_candidates/
└── ChinaStationHighway.shp
    # sample: ChinaStationHighway_demo.shp (+ sidecar files)

./data/input/temperature/
└── ChinaTemperature4Season.txt

./data/input/parameters/
├── TypicalVehicleBEVHFCV.txt
├── ChargingStation.txt
├── BatterySwapStation.txt
├── HydrogenRefuelingStation.txt
├── ChargingPost.txt
├── ElectricityPriceSummer.txt
├── ElectricityPriceUnsummer.txt
├── HydrogenPriceCG.txt
├── Parameters.txt
├── FreeSpeedByCategory.txt
├── BEVHFCVGHG.txt
├── BatteryGHG.txt
└── ProvinceCityCode.txt
```

Update the paths in:

```text
./codes/SimulationOptimization/config/parameters.yaml
```

to match your local data locations.

### Run

Run one season at a time, for example:

```bash
cd ./codes/SimulationOptimization
python main.py --season Winter --parallel
```

Other supported seasons are:

```text
Spring
Summer
Autumn
```

### Outputs

The Stage 4 results are saved under the configured `output_directory`.

Main optimization outputs include:

```text
optimization_history.csv
best_solution.pkl
best_objectives.csv
pareto_front.csv
pareto_solutions.pkl
best_compromise.json
```

Main simulation outputs include:

```text
01ElectrifiedVehicle.txt
02Station.txt
03PathExecution.txt
04Objective.txt
05AlgorithmRelated.txt
06ParkingRecord.txt
07DrivingTimeStatistics.txt
08StationServiceRecords.txt
```

Additional folders include:

```text
figures/
cache/
intermediate/
```

The results can be used to reproduce the fleet composition, infrastructure configuration, operational performance, and Pareto trade-off analyses reported in the manuscript.
